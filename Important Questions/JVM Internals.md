## Q1. What is the difference between JDK, JRE, and JVM?

### Answer

- **JDK (Java Development Kit)**: Used to develop Java applications.
    It contains the JRE and development tools like `javac`, `jar`,
    `javadoc`, and debuggers.
- **JRE (Java Runtime Environment)**: Used to run Java applications.
    It contains the JVM and Java runtime libraries.
- **JVM (Java Virtual Machine)**: Executes Java bytecode (`.class`
    files), performs memory management, garbage collection, and JIT
    compilation.

### Relationship

```
JDK
 └── JRE
      └── JVM
```

## Q2. What happens when you start a Java application?

### Answer

1. JVM process starts.
2. Memory regions are created (Heap, Stack, Metaspace, Code Cache, PC

    Registers, Native Stack).

3. Class Loaders load required classes.
4. Bytecode is verified.
5. Classes are linked.
6. Static variables and static blocks are initialized.
7. JVM invokes `public static void main(String[] args)`.
8. Interpreter begins executing bytecode.
9. JIT compiles frequently executed ("hot") methods into native machine

    code.

10. Garbage Collector manages heap memory during execution.

## Q3. What are the Class Loaders?

### Answer

1. **Bootstrap ClassLoader**

    - Loads core Java classes (`java.lang.*`, `java.util.*`).

2. **Platform (Extension) ClassLoader**

    - Loads JDK platform libraries.

3. **Application ClassLoader**

    - Loads application classes from the classpath.
        Delegation Model:
        Application
        ↓
        Platform
        ↓
        Bootstrap

## Q4. How does the JVM execute code?

### Answer

Initially, the JVM **interprets** bytecode.
When methods become "hot": - JIT compiler converts them into native
machine code. - Native code is stored in the **Code Cache**. - Future
executions use compiled code instead of interpretation.

## Q5. Why does Java use both an Interpreter and JIT Compiler?

### Answer

Interpreter: - Fast startup - Executes bytecode
instruction-by-instruction
JIT Compiler: - Optimizes frequently executed methods - Produces native
machine code - Improves long-running application performance

## Q7. What is Heap?

### Answer

Stores: - Objects - Arrays - Instance variables
Managed by: - Garbage Collector

## Q8. What is Stack?

### Answer

Each thread gets its own stack.
Each method call creates a new stack frame containing: - Local
variables - Parameters - Operand stack - Return information
Frames are removed when methods return.

## Q9. What is Metaspace?

### Answer

Stores: - Class metadata - Static fields - Runtime constant pool -
Method metadata
Introduced in Java 8 replacing PermGen.

## Q10. What is Code Cache?

### Answer

Stores machine code generated by the JIT compiler.

## Q11. Does the Garbage Collector run as a daemon thread?

### Answer

Yes.
GC threads are daemon threads.
They do not keep the JVM alive. Once all user (non-daemon) threads
finish, the JVM exits.

## Q12. Name some JVM daemon threads.

### Answer

- Garbage Collector threads
- JIT Compiler threads
- Reference Handler thread
- Finalizer thread (legacy)
- Other JVM service/housekeeping threads

# String Pool

## Q13. Where is the String Pool located?

### Answer

Since **Java 7**, the String Pool resides in the **Heap**.
Before Java 7: - PermGen
Java 7+: - Heap

## Q14. What happens with a String literal?

Java

```
String s = "hello";
```

### Answer

- JVM checks the String Pool.
- If `"hello"` exists, reuse it.
- Otherwise, create it in the String Pool.
- No new heap object outside the pool is created.

## Q15. What happens with `new String()`?

Java

```
String s = new String("hello");
```

### Answer

1. JVM ensures `"hello"` exists in the String Pool.
2. If absent, it is added.
3. `new` always creates a separate String object on the heap.
4. `s` references the new heap object.

    Possible outcome:

    If literal absent: - 1 pooled String - 1 heap String

    If literal already exists: - only the new heap String is created.

## Q16. What does `intern()` do?

Java

```
String s1 = new String("hello");
String s2 = s1.intern();
```

### Answer

`intern()` returns the canonical pooled String.
If the string exists in the pool: - Returns the pooled reference.
Otherwise: - Adds it to the pool and returns that reference.
s1 == s2 // usually false
s1.equals(s2) // true

## Q17. Are pooled Strings garbage collected?

### Answer

Yes.
Since the String Pool is in the Heap, pooled strings are eligible for
garbage collection when no longer strongly reachable.
