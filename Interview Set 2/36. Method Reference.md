[[15. Describe features of java 8]]
A Method Reference is a shorthand syntax for a lambda expression that simply invokes an existing method.

> [!Interview Answer]
>  A Method Reference is a shorthand syntax for a lambda expression that simply calls an existing method or constructor. It improves readability by eliminating unnecessary lambda parameters. A Method Reference can refer to a static method, an instance method of a particular object, an instance method of an arbitrary object of a particular type, or a constructor. It can only be used when the lambda directly delegates to an existing method without adding extra logic.

#### Why Do We Need Method References?

Suppose we have:
```
List<String> list = List.of("A", "B", "C");
```

Lambda:
```
list.forEach(s -> System.out.println(s));
```

The lambda does nothing except call:
```
System.out.println(s);
```

So Java lets us shorten it:
```
list.forEach(System.out::println);
```

Exactly the same behavior.

---
#### When Can We Use Method Reference?

Only when the lambda **does nothing except call another method**.

Example:
```
x -> x.length()
```
↓
```
String::length
```

---

Example:
```
x -> System.out.println(x)
```
↓
```
System.out::println
```

---
Cannot use Method Reference:
```
x -> x.length() + 1
```

because there is extra logic.

#### Types of Method References
There are **4 types**.

---
##### Static Method Reference
Class:
```
class MathUtil {
    static int square(int x) {
            return x * x;
                }}
```

Lambda:
```
Function<Integer, Integer> f =        
x -> MathUtil.square(x);
```

Method Reference:
```
Function<Integer, Integer> f =
        MathUtil::square;
```
---
##### Instance Method of a Particular Object
Suppose:
```
Printer printer = new Printer();
```

Lambda:
```
Consumer<String> c =
        s -> printer.print(s);
```

Method Reference:
```
Consumer<String> c =
        printer::print;
```
---
#### Instance Method of an Arbitrary Object
This one confuses many people.
Lambda:
```
Function<String, Integer> f =
        s -> s.length();
```

Method Reference:
```
Function<String, Integer> f =
        String::length;
```
There is no specific String object.

Java understands:
```
For any String passed in,call its length() method.
```
Another example:
```
Comparator<String> cmp =
        (a, b) -> a.compareToIgnoreCase(b);
```
Method Reference:
```
Comparator<String> cmp =
        String::compareToIgnoreCase;
```
---
#### Constructor Reference
Lambda:
```
Supplier<List<String>> supplier = 
       () -> new ArrayList<>();
```

Method Reference:
```
Supplier<List<String>> supplier =
        ArrayList::new;
```

An interviewer may ask:

```
list.forEach(System.out::println);
```

**Question:** _How does the compiler know what parameter to pass to `println()`?_

The answer is:

- `forEach()` expects a `Consumer<T>`.
- `Consumer<T>` has one method:

```
void accept(T t);
```

- The stream passes each element to `accept()`.
- `System.out::println` matches the signature of `accept(T)`, so the compiler binds each element to the `println()` method automatically through the target functional interface. This is an excellent example of how **Functional Interfaces, Lambdas, and Method References all work together**.
