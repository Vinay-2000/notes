# What is the Diamond Problem?

The diamond problem occurs when a class inherits the **same method from multiple interfaces**, creating ambiguity about which implementation should be used.

Example:

```
        Vehicle
         /    \
        /      \
CarInterface  BoatInterface
        \      /
         \    /
      AmphibiousCar
```

Both interfaces provide the same default method.
Complie time error - Practice inherits unrelated defaults for start() from types Vehicle and Car

Java defines **3 rules**.
## Rule 1: Class Wins Over Interface

If a superclass already provides the method, it takes precedence over any default method in interfaces.
Example:
```
class Vehicle {

    public void start() {
        System.out.println("Vehicle Started");
    }
}

interface Car {

    default void start() {
        System.out.println("Car Started");
    }
}

class MyCar extends Vehicle implements Car {

}
```
Output:
```
Vehicle Started
```

## Rule 2: More Specific Interface Wins

Suppose:
```
interface Vehicle {

    default void start() {
        System.out.println("Vehicle");
    }
}

interface Car extends Vehicle {

    default void start() {
        System.out.println("Car");
    }
}

class BMW implements Car {

}
```
Output:

```
Car
```

## Rule 3: If Ambiguity Remains, You Must Override

Suppose:

```
interface Car {

    default void start() {
        System.out.println("Car");
    }
}

interface Boat {

    default void start() {
        System.out.println("Boat");
    }
}
```

Now:

```
class AmphibiousVehicle implements Car, Boat {

}
```

Compiler says:

```
I don't know which one to use.
```

You must override:

```
class AmphibiousVehicle implements Car, Boat {

    @Override
    public void start() {

        Car.super.start();

        // or Boat.super.start();
    }
}
```

or provide your own implementation.
#### Calling a Specific Interface

Java allows:

```
Car.super.start();
```

or

```
Boat.super.start();
```

This is unique to default methods.
