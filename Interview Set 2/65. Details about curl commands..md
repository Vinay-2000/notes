## 1. cURL

**cURL** is a command-line tool used to make HTTP/network requests.

Commonly used to test REST APIs without a browser.

### Basic Examples

```
# GET
curl http://localhost:8080/users

# POST
curl -X POST http://localhost:8080/users \
  -H "Content-Type: application/json" \
  -d '{"name":"John","age":30}'

# PUT
curl -X PUT http://localhost:8080/users/10

# PATCH
curl -X PATCH http://localhost:8080/users/10

# DELETE
curl -X DELETE http://localhost:8080/users/10
```

### Important Options

|Option|Meaning|
|---|---|
|`-X` / `--request`|Specify HTTP method|
|`-H` / `--header`|Add HTTP header|
|`-d` / `--data`|Send request body|
|`-v` / `--verbose`|Show detailed request/response information|

Example:

```
curl -X POST http://localhost:8080/users \
  -H "Content-Type: application/json" \
  -d '{"name":"John"}'
```

Here:

- `-X POST` → HTTP method
- `-H` → Content-Type header
- `-d` → request body

### Interview Point

> `**-X**` **specifies the HTTP method used by cURL.**

`-X` is shorthand for `--request`.

# 2. CORS

**CORS (Cross-Origin Resource Sharing)** is a browser security mechanism that controls whether JavaScript from one origin can access resources from another origin.

### Origin

An origin consists of:

```
scheme + host + port
```

Example:

```
Frontend: http://localhost:3000
Backend:  http://localhost:8080
```

These are different origins because the ports differ.

Therefore, a browser may block the frontend from accessing the backend unless the backend allows it through CORS.

### How CORS Works

Backend can return headers such as:

```
Access-Control-Allow-Origin: http://localhost:3000
```

This tells the browser that the frontend origin is allowed to access the response.

### Preflight Request

For certain cross-origin requests, the browser first sends:

```
OPTIONS /users
```

This is called a **preflight request**.

The server responds with allowed methods/headers, for example:

```
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
```

If the CORS check succeeds, the browser sends the actual request.

### Important Interview Point

CORS is primarily a **browser-enforced security mechanism**.

Tools such as:

- cURL
- Postman

do **not** enforce the browser's Same-Origin Policy.

Therefore:

> An API can work perfectly in Postman/cURL but fail with a CORS error in the browser.

CORS does **not** prevent someone from calling your API using cURL/Postman. It controls browser-based JavaScript access.

## Quick Interview Questions

**Q: What is cURL?**

> A command-line tool used to make HTTP/network requests, commonly used for testing APIs.

**Q: What does** `**-X**` **do in cURL?**

> It specifies the HTTP method, such as GET, POST, PUT, PATCH, or DELETE.

**Q: What is CORS?**

> CORS is a browser security mechanism that controls cross-origin requests from JavaScript.

**Q: Why does Postman work but the browser gives a CORS error?**

> Postman doesn't enforce the browser's Same-Origin Policy, while browsers enforce CORS rules.

**Q: What is a CORS preflight?**

> An `OPTIONS` request sent by the browser before certain cross-origin requests to check whether the actual request is permitted.
