Key difference - **"throws CME vs doesn't throw CME."**
CME - ConcurrentModificationException

| Aspect                            | Fail-Fast Iterator                                     | Fail-Safe* Iterator                                      |
| --------------------------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| Concurrent modification           | Detects structural modification during iteration       | Can tolerate concurrent modification                     |
| `ConcurrentModificationException` | Usually throws `ConcurrentModificationException`       | Generally does not throw CME                             |
| Works on                          | Original collection                                    | Often works on a copy/snapshot or weakly consistent view |
| Reflection of changes             | Typically not guaranteed; iteration may stop with CME  | Depends on implementation; may or may not see changes    |
| Example                           | `ArrayList`, `HashMap`, `HashSet`                      | `CopyOnWriteArrayList`                                   |
| Performance                       | Usually less overhead                                  | Copying/snapshotting can have overhead                   |
| Guarantee                         | **Best-effort detection**, not a concurrency guarantee | Behavior depends on the collection                       |

### Fail-safe example

```
CopyOnWriteArrayList<Integer> list =
        new CopyOnWriteArrayList<>(List.of(1, 2, 3));

for (Integer i : list) {
    list.add(4);   // No CME
}
```

`CopyOnWriteArrayList` iterators operate over a snapshot of the array, so modification doesn't break the ongoing iteration.

> **ConcurrentHashMap iterators are weakly consistent.**

**Weakly consistent** means the iterator of `ConcurrentHashMap` can continue iterating while the map is being modified by another thread.

It **doesn't throw `ConcurrentModificationException`**, but it also **doesn't guarantee that the iterator sees a perfect snapshot of the map**.

---
#### Why does `ArrayList` throw CME if I modify it during iteration?

Because ArrayList's iterator uses modCount and expectedModCount to detect structural modifications.


`modCount` is a field in `AbstractList`, inherited by `ArrayList`. It is maintained by the collection and is incremented when **structural modifications** occur. When an iterator is created, it captures the current `modCount` as `expectedModCount`. During iteration, the iterator compares them. If they differ, it indicates that the collection was structurally modified outside the iterator, so the iterator throws `ConcurrentModificationException`.


#### Important: `Iterator.remove()` is different

This is allowed:
```
Iterator<Integer> it = list.iterator();

while (it.hasNext()) {
    Integer value = it.next();

    if (value == 2) {
        it.remove();  // ✅
    }
}
```
Why?
Because the iterator itself performs the modification and can update its internal `expectedModCount` accordingly.
