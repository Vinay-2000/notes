# What is Bean Scope?

A bean scope defines:
> **How many instances of a bean Spring should create and how long those instances should live.**

### **Bean Scopes:**
`@Scope("prototype")` can be used with both `@Component` and `@Bean` because scope configuration applies to the Spring bean definition itself, regardless of how the bean is registered in the application context.

| Scope         | Meaning                   |
| ------------- | ------------------------- |
| `singleton`   | One bean per container    |
| `prototype`   | New bean every request    |
| `request`     | One bean per HTTP request |
| `session`     | One bean per HTTP session |
| `application` | Shared across web app     |
Bean scope in Spring defines how many instances of a bean are created and how long they live within the IoC container.
The default scope is Singleton, where Spring creates one instance per ApplicationContext and shares it across the application. Prototype scope creates a new bean instance every time it is requested from the container. 
Request scope, used in web applications, creates one bean instance for each HTTP request and destroys it when the request completes.
Spring manages singleton beans completely, including creation and destruction, while for prototype beans it only manages creation. All singleton beans are stored in the ApplicationContext and reused wherever they are injected.
A common consideration is that when a prototype bean is injected into a singleton bean, the prototype is created only once during injection unless techniques like ObjectProvider or @Lookup are used to obtain fresh instances.

1. Bean scope controls lifecycle and number of instances.
2. Singleton is default and stored in ApplicationContext.
3. Prototype creates a new instance every request from the container.
4. Request scope creates one bean per HTTP request.
5. Singleton beans are eagerly created.
6. Prototype beans are lazily created.
7. Singleton injecting prototype does not automatically create new instances.
8. Spring manages the full lifecycle of singleton beans but not destruction of prototype beans.
## Q: Where are singleton beans stored?
Inside the `ApplicationContext` singleton cache.

---

## Q: Does Spring eagerly create singleton beans?

Yes, by default during context startup.

Exception:

```
@Lazy
```

---

## Q: Does Spring eagerly create prototype beans?

No.

They are created only when requested.

---

## Q: Does Spring manage destruction of prototype beans?

No.

Spring only creates them.

Client code is responsible for cleanup.

---

## Q: Are singleton beans thread-safe?

Not automatically.

Spring guarantees:

```
Single Instance
```

It does NOT guarantee:

```
Thread Safety
```

Avoid mutable shared state.
