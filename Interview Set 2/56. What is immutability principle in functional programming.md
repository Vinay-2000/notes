In **functional programming**, immutability means:

> **Once a value/object is created, you don't change it. Instead, you create a new value with the desired change.**

### Immutable approach

Instead of modifying the existing list:

```
List<Integer> numbers = List.of(1, 2);

List<Integer> newNumbers = new ArrayList<>(numbers);
newNumbers.add(3);
```

Conceptually:

```
numbers     → [1, 2]
newNumbers  → [1, 2, 3]
```

The original `numbers` remains unchanged.

### Why does functional programming care about this?

Consider:

```
int calculateTotal(List<Integer> numbers) {
    numbers.add(100);       // modifies input
    return ...
}
```

Now calling the function can unexpectedly change something outside the function.

With immutability:

```
int calculateTotal(List<Integer> numbers) {
    // only reads numbers
    return ...
}
```

The function doesn't modify its input, so you get a much stronger guarantee:

```
Input → Function → Output
```

rather than:

```
Input → Function → Output
  ↑
  └── may have been secretly modified
```

This makes functional programs easier to **reason about, test, debug, and run concurrently**.
