## 1. What is IoC?

**IoC (Inversion of Control)** means transferring the responsibility of **creating, configuring, and managing objects** from your application code to an external container/framework.
Without IoC:

```
OrderService service = new OrderService();
```

Your code controls object creation.
With Spring:

```
@Autowired
OrderService service;
```

Spring's IoC container controls:

- Object creation
- Dependency injection
- Bean lifecycle
- Bean scope

### IoC vs DI

> **IoC is the principle; DI is a technique used to achieve IoC.**
> For example, Spring performs IoC by using dependency injection.

## 2. How can we create a custom IoC container? How does it work?

Yes, we can create a basic IoC container ourselves **without Spring**.
At a high level, we need:

```
IoC Container
     |
     ↓
Map<Class, Object>
```

The container can:

1. **Register/discover classes** that should be managed.
2. Use **reflection** to create objects.
3. Inspect the constructor to find dependencies.
4. Recursively create/find those dependencies.
5. Inject them through the constructor.
6. Store the created object in the container.
7. Return the same managed object when requested, depending on the configured scope.
   Example:

```
class OrderService {
    private final PaymentService paymentService;
    OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
```

When we request:

```
context.getBean(OrderService.class);
```

the container conceptually does:

```
OrderService needed
       ↓
Find constructor
       ↓
Needs PaymentService
       ↓
Create/get PaymentService
       ↓
Pass it to OrderService constructor
       ↓
Create OrderService
       ↓
Store/manage it
```

Spring's IoC container does this much more extensively with **component scanning, bean definitions, scopes, lifecycle callbacks, configuration, proxies/AOP, etc.**

### Interview point

You should be able to explain:

> "A basic IoC container can use a registry such as `Map<Class<?>, Object>`, reflection for object creation, and recursive dependency resolution. Spring's container builds on this idea and provides much more functionality."

# A basic custom IoC container

For interview understanding, something like this is enough:

```
class ApplicationContext {

    private final Map<Class<?>, Object> beans = new HashMap<>();

    public <T> T getBean(Class<T> type) {

        if (beans.containsKey(type)) {
            return type.cast(beans.get(type));
        }

        try {
            Constructor<?> constructor =
                    type.getConstructors()[0];

            Class<?>[] parameterTypes =
                    constructor.getParameterTypes();

            Object[] dependencies = new Object[parameterTypes.length];

            for (int i = 0; i < parameterTypes.length; i++) {
                dependencies[i] = getBean(parameterTypes[i]);
            }

            Object object =
                    constructor.newInstance(dependencies);

            beans.put(type, object);

            return type.cast(object);

        } catch (Exception e) {
            throw new RuntimeException(e);
        }
    }
}
```
