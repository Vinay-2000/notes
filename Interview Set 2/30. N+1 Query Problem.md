[[26. JPA]]

### Interview Answer

The N+1 Query Problem occurs when Hibernate executes one query to load parent entities and then executes one additional query for each parent entity to fetch its associated child entities. This usually happens with lazy-loaded relationships when child collections are accessed inside a loop. The result is excessive database queries and degraded performance. The most common solutions are using `JOIN FETCH` in JPQL, `@EntityGraph` for declarative fetching, or batch fetching to reduce the number of SQL queries. Using `FetchType.EAGER` alone does not reliably solve the N+1 problem.
The N+1 Query Problem occurs when Hibernate executes **one query to fetch parent entities** and then executes **one additional query for each parent** to fetch its associated child entities.

As a result, instead of executing **1 query**, Hibernate executes **N+1 queries**, causing unnecessary database calls and poor performance.

---

## Why Does N+1 Happen?

Suppose we have the following entities:

```java
@Entity
class Department {

    @Id
    private Long id;

    @OneToMany(mappedBy = "department")
    private List<Employee> employees;
}
```

```java
@Entity
class Employee {

    @ManyToOne
    @JoinColumn(name = "department_id")
    private Department department;
}
```

Database:

```text
Department
----------
1 IT
2 HR
3 Finance
```

```text
Employee
-------------------------
101 Vinay   1
102 Rahul   1
103 Amit    2
104 John    3
```

---

## Internal Working of N+1

Suppose:

```java
List<Department> departments =
        repository.findAll();
```

Hibernate executes:

```sql
SELECT * FROM department;
```

Result:

```text
IT
HR
Finance
```

Now later:

```java
for (Department d : departments) {

    d.getEmployees().size();

}
```

Since `employees` is LAZY:

Hibernate executes:

```sql
SELECT * FROM employee
WHERE department_id = 1;
```

Then:

```sql
SELECT * FROM employee
WHERE department_id = 2;
```

Then:

```sql
SELECT * FROM employee
WHERE department_id = 3;
```

Total queries:

```text
1 query (Departments)

+

3 queries (Employees)

=

4 queries
```

If there are:

```text
100 Departments
```

Then:

```text
1 + 100 = 101 Queries
```

Hence the name:

```text
N + 1
```

---

## N+1 Flow

```text
Load Departments
        |
1 SQL Query
        |
Loop Departments
        |
Load Employees
        |
One Query Per Department
```

---

## Why Is It Bad?

Suppose:

```text
1000 Departments
```

Hibernate executes:

```text
1 + 1000 SQL Queries
```

Instead of:

```text
1 SQL Query
```

The application becomes much slower because of excessive database round trips.

---

## Solution 1 - JOIN FETCH (Most Common)

JPQL:

```java
@Query("""
SELECT d
FROM Department d
JOIN FETCH d.employees
""")
List<Department> findAllWithEmployees();
```

Hibernate generates:

```sql
SELECT *
FROM department d
JOIN employee e
ON d.id = e.department_id;
```

Now:

```text
One SQL Query
```

No additional queries.

This is the most common interview answer.

---

## Solution 2 - @EntityGraph

```java
@EntityGraph(attributePaths = "employees")
List<Department> findAll();
```

Hibernate automatically fetches:

```text
Department

+

Employees
```

using one optimized query.

No JPQL required.

---

## Solution 3 - Batch Fetching

Hibernate can batch lazy loading.

Example:

```properties
hibernate.default_batch_fetch_size=20
```

Instead of:

```text
100 Queries
```

Hibernate loads:

```text
20 Departments at once
```

reducing the number of SQL statements.

---

## Does EAGER Solve N+1?

Not necessarily.

Many people think:

```java
@OneToMany(fetch = FetchType.EAGER)
```

solves the problem.

It doesn't.

Hibernate may still execute:

```text
1 + N Queries
```

depending on how the query is written.

EAGER means:

> "Load immediately."

It does **not** guarantee a SQL JOIN.

---

## Common Interview Questions on N+1

### What causes the N+1 Query Problem?

Accessing lazy-loaded associations inside a loop.

---

### Which relationship commonly causes N+1?

Usually:

```java
@OneToMany
```

or

```java
@ManyToMany
```

because they default to LAZY loading.

However, N+1 can occur with any association if Hibernate issues separate queries.

---

### Best solution?

Usually:

```text
JOIN FETCH
```

or

```text
@EntityGraph
```

---

### Does First Level Cache solve N+1?

No.

Each employee is still loaded with a separate SQL query.

The cache only prevents loading the **same entity twice** within a session.

---

### Does Second Level Cache solve N+1?

Not really.

It may reduce some database hits if child entities are already cached, but Hibernate still has to resolve each association. The underlying N+1 access pattern remains.
