# 2. Difference between @Mock and @MockBean

|`@Mock`|`@MockBean`|
|---|---|
|Mockito annotation|Spring Boot annotation|
|Doesn't start Spring Context|Starts Spring Test Context|
|Used in Unit Tests|Used in Integration Tests|
|Creates plain mock object|Replaces bean inside ApplicationContext|
|Faster|Slower|

Example:

```
@Mock
UserRepository repository;
```

Mockito creates the mock.

---

```
@SpringBootTest
@MockBean
UserRepository repository;
```

Spring replaces the real `UserRepository` bean with a mock.

### Interview Question

**When to use which?**

- `@Mock` → Unit testing
- `@MockBean` → Spring Boot integration testing
# 3. How can we avoid mocking the Repository?

Instead of mocking:

```
@Mock
UserRepository repository;
```

Use an **in-memory database**.

Example:

```
@DataJpaTest
```

Spring automatically configures:

```
H2 Database
Hibernate
Repositories
```

Now you're testing the real repository.

Example:

```
@DataJpaTest
class UserRepositoryTest {}
```

### Other options

- Testcontainers (real PostgreSQL/MySQL)
- H2 Database

### Interview Tip

Repository tests should generally test actual database behavior instead of mocking.

# 4. What is Spy?

A Spy wraps a **real object**.

Real methods execute unless stubbed.

```
List<String> list = new ArrayList<>();
List<String> spy = Mockito.spy(list);
```

Now:

```
spy.add("A");
```

actually adds.

But:

```
doReturn(100).when(spy).size();
```

overrides only:

```
size()
```

Everything else remains real.

---

## Mock vs Spy

|Mock|Spy|
|---|---|
|Fake object|Real object wrapper|
|Methods return defaults|Real methods execute|
|Everything mocked|Partial mocking|
# 5. How to Mock Static Methods?

Mockito 3.4+ supports it.

```
try (MockedStatic<LocalDate> mock =

    mock.when(LocalDate::now)

    }
```

Useful for:

```
UUID.randomUUID()LocalDate.now()Instant.now()
```


# 7. What is an Argument Matcher?

Mockito uses argument matchers to match method parameters without requiring exact values.

Example:

Instead of:

```
when(repo.findById(1L))
```

use:

```
when(repo.findById(anyLong()))
```

Now:

```
findById(1)
findById(2)
findById(100)

```

all match.

---

```

```

## WireMock

This is a common Spring Boot testing interview question, especially if you've worked with microservices.

# What is WireMock?

**WireMock is a tool that simulates (mocks) external HTTP services.**

Instead of calling a real external API during tests, your application calls **WireMock**, which returns predefined responses.

---

# Why do we need WireMock?

Suppose your service calls an external payment API.

```text
Your Service
      │
      ▼
Payment Service (External)
```

Problems during testing:

- External service may be down.
    
- Slow network.
    
- Test depends on another team's API.
    
- API may return different data every time.
    

Instead, use WireMock.

```text
Your Service
      │
      ▼
WireMock Server
      │
Returns fake HTTP responses
```

Now your tests are:

- Fast
    
- Repeatable
    
- Independent of external systems
    

---

# Example Scenario

Suppose your service uses `RestTemplate`.

```java
@Service
public class UserService {

    @Autowired
    private RestTemplate restTemplate;

    public User getUser() {
        return restTemplate.getForObject(
            "http://user-service/users/1",
            User.class);
    }
}
```

Normally:

```text
RestTemplate
      │
      ▼
Real User Service
```

During testing:

```text
RestTemplate
      │
      ▼
WireMock
```

---

# How WireMock Works

You tell WireMock:

> "If someone calls this URL, return this response."

Example:

```java
stubFor(get(urlEqualTo("/users/1"))
    .willReturn(aResponse()
        .withStatus(200)
        .withHeader("Content-Type", "application/json")
        .withBody("""
            {
              "id":1,
              "name":"Vinay"
            }
        """)));
```

Now when your application makes:

```http
GET /users/1
```

WireMock returns:

```json
{
  "id":1,
  "name":"Vinay"
}
```

without calling a real server.

---

# Example Test

```java
@SpringBootTest
class UserServiceTest {

    @Test
    void shouldReturnUser() {

        stubFor(get("/users/1")
            .willReturn(okJson("""
                {
                  "id":1,
                  "name":"Vinay"
                }
            """)));

        User user = service.getUser();

        assertEquals("Vinay", user.getName());
    }
}
```

# Why Not Just Mock RestTemplate?

You could.

Example:

```java
@Mock
RestTemplate restTemplate;
```

But then you're only testing:

```text
UserService logic
```

You're **not** testing:

- HTTP request
    
- URL construction
    
- Headers
    
- JSON serialization
    
- Deserialization
    

WireMock tests the complete HTTP interaction.

---

# Mock vs WireMock

|Mockito|WireMock|
|---|---|
|Mocks Java methods|Mocks HTTP endpoints|
|Unit Testing|Integration Testing|
|Doesn't start HTTP server|Starts fake HTTP server|
|`when().thenReturn()`|`stubFor().willReturn()`|
|Tests Java code|Tests REST communication|

# Common Interview Questions

### Q: Does WireMock replace RestTemplate?

No.

It replaces the **external server**, not the client.

```text
RestTemplate
      │
      ▼
WireMock
```

instead of

```text
RestTemplate
      │
      ▼
Real API
```

---

### Q: Can WireMock simulate failures?

Yes.

Examples:

- 404
    
- 500
    
- Timeout
    
- Delays
    
- Invalid JSON
    
- Network errors
    

---

### Q: Is WireMock used for unit testing?

Generally no.

It's primarily used for:

```text
Integration Testing
```

where you want to test real HTTP communication without depending on external services.

---

# Interview-Ready Answer

> WireMock is an HTTP mocking framework used to simulate external REST APIs during testing. It starts a lightweight HTTP server that returns predefined responses for configured requests, allowing applications to test REST communication without calling real external services. This makes tests faster, reliable, and independent of network availability. WireMock can simulate various scenarios such as successful responses, 404 and 500 errors, delays, and malformed responses. It is commonly used in integration testing with `RestTemplate`, `WebClient`, or other HTTP clients to verify request handling and response processing.

## One interview distinction to remember

|Tool|Purpose|
|---|---|
|**Mockito**|Mock Java methods and objects (`@Mock`, `@Spy`)|
|**MockMvc**|Test your own Spring MVC controllers without starting a real server|
|**WireMock**|Mock **external HTTP services** that your application calls|

This distinction is asked very frequently in Spring Boot interviews.
