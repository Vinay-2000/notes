### 1. AUTO
```
@Id
@GeneratedValue(strategy = GenerationType.AUTO)
private Long id;
```

You let Hibernate decide.

For example:

| Database   | Strategy Hibernate Usually Chooses |
| ---------- | ---------------------------------- |
| MySQL      | IDENTITY                           |
| PostgreSQL | SEQUENCE                           |
| Oracle     | SEQUENCE                           |
| SQL Server | IDENTITY                           |
| H2         | Depends on configuration           |
### 2. IDENTITY

Example:

```
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

Database table:

```
CREATE TABLE employee (
    id BIGINT AUTO_INCREMENT,
    name VARCHAR(100)
);
```

When Hibernate executes:

```
INSERT INTO employee(name)
VALUES('Vinay');
```

Database generates:

```
id = 101
```

Hibernate asks database:

```
"What ID did you generate?"
```

Database returns:

```
101
```

### Why Batch Inserts don't work?

Hibernate doesn't know IDs beforehand.

It must:

```
Insert Row
      |
Wait for generated ID
      |
Insert next row
```


## 3. SEQUENCE

```
@Id
@GeneratedValue(strategy = GenerationType.SEQUENCE)
private Long id;
```

Database has:

```
CREATE SEQUENCE employee_seq;
```

Before inserting:

Hibernate executes:

```
SELECT employee_seq.NEXTVAL;
```

Suppose:

```
501
```

Now Hibernate already knows:

```
Employee ID = 501
```

Then:

```
INSERT INTO employee(id,name)
VALUES(501,'Vinay');
```

Since Hibernate already knows IDs, it can batch multiple inserts.

Example:

```
NEXTVAL → 501
NEXTVAL → 502
NEXTVAL → 503
Batch Insert
```

Much faster.

```
@GeneratedValue(
    strategy = GenerationType.SEQUENCE,
    generator = "emp_seq"
)

@SequenceGenerator(
    name = "emp_seq",
    sequenceName = "employee_seq",
    allocationSize = 1
)

```

#### What is `allocationSize`?

`allocationSize` tells Hibernate:

> **How many IDs should I reserve from the database sequence in one database call?**

Default:

```
allocationSize = 50
```

`allocationSize` specifies how many sequence values Hibernate reserves from the database in a single call. With `allocationSize = 1`, Hibernate requests the next sequence value for every insert, resulting in more database round trips but minimal gaps in IDs. With larger values, such as the default `50`, Hibernate reserves a block of IDs and uses them from memory, significantly improving insert performance by reducing sequence calls. Larger allocation sizes may result in gaps if the application stops before all reserved IDs are used, but this is generally acceptable since primary keys only need to be unique, not sequential.

## 4. TABLE

Hibernate creates a table like:

```
id_generator
-----------------------
entity_name | next_id
-----------------------
employee    | 101
customer    | 51
```

When inserting:

Hibernate:

```
SELECT next_id
FROM id_generator
WHERE entity_name='employee';
```

Gets:

```
101
```

Updates:

```
UPDATE id_generator
SET next_id=102
WHERE entity_name='employee';
```

Finally:

```
INSERT INTO employee(id,name)
VALUES(101,'Vinay');
```

Notice:

One insert requires:

- SELECT
- UPDATE
- INSERT

Three database operations.

This is why it's the slowest.
