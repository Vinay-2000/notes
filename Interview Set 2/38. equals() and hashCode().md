## What are `equals()` and `hashCode()`?

Both methods are defined in `java.lang.Object`.

-   `equals()` determines **logical equality** between two objects.
-   `hashCode()` returns an integer hash value used by hash-based
    collections such as `HashMap` and `HashSet`.

------------------------------------------------------------------------

# equals()

## Default Implementation

The default implementation compares object references.

``` java
Employee e1 = new Employee(1);
Employee e2 = new Employee(1);

System.out.println(e1.equals(e2)); // false
```

This is equivalent to:

``` java
e1 == e2
```

To compare object contents, override `equals()`.

Example:

``` java
@Override
public boolean equals(Object obj) {
    if (this == obj) return true;
    if (obj == null || getClass() != obj.getClass()) return false;

    Employee other = (Employee) obj;
    return id == other.id;
}
```

------------------------------------------------------------------------

# hashCode()

Returns an integer hash value.

Hash-based collections use it to determine the bucket where an object
should be stored.

Example:

``` java
Employee e = new Employee(1);

System.out.println(e.hashCode());
```

------------------------------------------------------------------------

# How HashMap Uses Them

When inserting or searching for a key:

``` text
Key
 ↓
hashCode()
 ↓
Bucket
 ↓
equals()
 ↓
Object Found
```

1.  `hashCode()` determines the bucket.
2.  `equals()` compares objects only within that bucket.

------------------------------------------------------------------------

# Why Override hashCode()?

If two objects are equal according to `equals()`, they **must** return
the same hash code.

Suppose:

``` java
Employee e1 = new Employee(1);
Employee e2 = new Employee(1);

System.out.println(e1.equals(e2)); // true
```

If `hashCode()` is **not** overridden:

``` text
e1.hashCode() = 145678
e2.hashCode() = 987654
```

They go into different buckets.

``` text
Bucket 5
 └── e1

Bucket 12
 └── e2
```

Now:

``` java
HashSet<Employee> set = new HashSet<>();

set.add(e1);

System.out.println(set.contains(e2));
```

Output:

``` text
false
```

Reason:

`HashSet` looks only in the bucket determined by `e2.hashCode()`. Since
`e1` is in another bucket, `equals()` is never called.

Correct implementation:

``` java
@Override
public int hashCode() {
    return Integer.hashCode(id);
}
```

Now both objects have the same hash code, are placed in the same bucket,
and `equals()` correctly identifies them.

------------------------------------------------------------------------

# hashCode() Contract

1.  If two objects are equal (`equals()` returns `true`), they **must**
    have the same hash code.
2.  If two objects have the same hash code, they are **not necessarily
    equal**.
3.  During a single execution, `hashCode()` should consistently return
    the same value unless fields used in equality change.

------------------------------------------------------------------------

# Hash Collision

Two different objects may have the same hash code.

``` text
A → Bucket 5

B → Bucket 5
```

This is called a **hash collision**.

`equals()` is then used to distinguish them.

------------------------------------------------------------------------

# equals() Contract

-   Reflexive
-   Symmetric
-   Transitive
-   Consistent
-   Comparing with `null` returns `false`

------------------------------------------------------------------------

# equals() vs ==

  `==`                   `equals()`
  ---------------------- ---------------------------
  Compares references    Compares logical equality
  Cannot be overridden   Can be overridden
  Faster                 May compare object state

Example:

``` java
String s1 = new String("Java");
String s2 = new String("Java");

System.out.println(s1 == s2);      // false
System.out.println(s1.equals(s2)); // true
```

------------------------------------------------------------------------

# hashCode() vs equals()

  hashCode()                 equals()
  -------------------------- --------------------------
  Returns `int`              Returns `boolean`
  Finds bucket               Confirms equality
  Used first                 Used after hashCode()
  Used by hash collections   Defines logical equality

------------------------------------------------------------------------

# Common Interview Questions

## Why does HashMap call `hashCode()` before `equals()`?

Comparing integers is much faster than comparing objects. `hashCode()`
narrows the search to one bucket, then `equals()` identifies the correct
object.

------------------------------------------------------------------------

## Why must we override both?

If `equals()` is overridden without `hashCode()`, equal objects may be
placed in different buckets, causing `HashMap` and `HashSet` operations
like `contains()`, `get()`, and duplicate detection to fail.

------------------------------------------------------------------------

## Can two unequal objects have the same hash code?

Yes. This is called a hash collision.

------------------------------------------------------------------------

## Can two equal objects have different hash codes?

No. That violates the `hashCode()` contract.

------------------------------------------------------------------------

## What happens if many objects have the same hash code?

They are stored in the same bucket. `equals()` is used to locate the
correct object. Too many collisions degrade performance.

------------------------------------------------------------------------

## Time Complexity of HashMap

-   Average: **O(1)** for `put()` and `get()`
-   Worst case: **O(n)** (many collisions)
-   Since Java 8, heavily populated buckets are converted to balanced
    trees, improving worst-case lookups to **O(log n)** when
    treeification occurs.

------------------------------------------------------------------------

# Best Practices

-   Always override `hashCode()` whenever you override `equals()`.
-   Use the same fields in both methods.
-   Prefer `Objects.equals()` and `Objects.hash()`.

Example:

``` java
@Override
public boolean equals(Object obj) {
    if (this == obj) return true;
    if (!(obj instanceof Employee other)) return false;
    return id == other.id;
}

@Override
public int hashCode() {
    return Objects.hash(id);
}
```

------------------------------------------------------------------------

# Interview Answer

`equals()` defines logical equality between two objects, while
`hashCode()` generates an integer used by hash-based collections to
locate the correct bucket efficiently. `HashMap` and `HashSet` first
call `hashCode()` to identify the bucket and then call `equals()` to
find the exact object within that bucket. Therefore, whenever `equals()`
is overridden, `hashCode()` must also be overridden so that equal
objects produce the same hash code and behave correctly in hash-based
collections.
