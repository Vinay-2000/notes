## Interview Answer
Swagger is a set of tools built around the OpenAPI specification that helps document, test, and generate code for REST APIs. In our project, we used an OpenAPI YAML file to define the API contract, including endpoints, request and response schemas, status codes, and validations. 
Using Swagger Codegen/OpenAPI Generator, we generated DTOs and API interfaces from this specification. Our controllers implemented the generated interfaces, which ensured the implementation always matched the API contract. 
Swagger UI also provided an interactive web interface where consumers could view and test APIs. This contract-first approach improves consistency between documentation and implementation and reduces integration issues between teams.

Swagger is a set of tools used to **design, document, test, and generate code for REST APIs** based on the OpenAPI Specification.
- **OpenAPI** = Specification/standard
- **Swagger** = Tooling around that specification

# What is OpenAPI.yml?

You define your API contract in a file:

```
openapi: 3.0.0

paths:
  /users:
    get:
      summary: Get users
      responses:
        200:
          description: Success
```

This file describes:

- Endpoints
- HTTP methods
- Request parameters
- Request body
- Response body
- Status codes
- Security requirements
- Data models

It acts as a contract between API provider and API consumer.

## Code Generation Plugin
```
<plugin>
    <groupId>io.swagger.codegen.v3</groupId>
    <artifactId>swagger-codegen-maven-plugin</artifactId>
    <version>3.0.51</version>

    <executions>
        <execution>
            <goals>
                <goal>generate</goal>
            </goals>
        </execution>
    </executions>

    <configuration>
        <inputSpec>
            ${project.basedir}/src/main/resources/openapi.yml
        </inputSpec>

        <language>spring</language>

        <output>
            ${project.build.directory}/generated-sources/swagger
        </output>
    </configuration>
</plugin>
```

We maintained an OpenAPI YAML specification and used the Swagger Codegen Maven Plugin during the Maven build lifecycle. The plugin was configured in the `<build><plugins>` section of the pom.xml and executed during the generate-sources phase. When running `mvn clean install`, it generated DTOs and API interfaces from the OpenAPI specification, typically under `target/generated-sources`. Maven automatically added those generated classes to the compilation classpath, allowing our controllers to implement the generated interfaces and ensuring the implementation matched the API contract.
