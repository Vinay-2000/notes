**JPA (Jakarta Persistence API)** is the standard specification in Java for Object-Relational Mapping (ORM). Instead of manually writing JDBC SQL code, mapping `ResultSet` rows to Java objects, and handling connection pools yourself, JPA automates the bridge between relational tables and object-oriented code.

- **Dramatically Reduces Boilerplate:** Eliminates repetitive SQL string building, parameter mapping, and connection open/close loops.
    
- **Database Independence (Portability):** JPA uses JPQL (Jakarta Persistence Query Language). Switching underlying databases (e.g., PostgreSQL to MySQL) requires changing a configuration dialect—not rewriting thousands of query strings.
    
- **First-Level & Second-Level Caching:** Tracks loaded entities in memory (the _Persistence Context_). If an entity is requested twice in one transaction, JPA serves it from cache without firing an extra SQL query.
    
- **Object Relationship Management:** Easily maps complex database relationships (`@OneToMany`, `@ManyToOne`, `@ManyToMany`) directly into Java collection fields with lazy or eager fetching strategies.
    
- **Automatic Schema Generation:** Can auto-generate database DDL scripts (tables, keys, indexes) directly from your annotated domain entities during development


---

JPA (Java Persistence API) is a specification that provides an object-oriented way to interact with relational databases. Hibernate is the most popular implementation of JPA.

## Advantages

### 1. No SQL for Common Operations

Instead of writing SQL,

```
SELECT * FROM employee WHERE id = 1;
```

You simply write

```
employeeRepository.findById(1L);
```

---

### 2. Object Relational Mapping (ORM)

Maps Java objects to database tables.

```
@Entity
public class Employee {

    @Id
    private Long id;

    private String name;
}
```

JPA automatically maps this to

```
EMPLOYEE
---------
ID
NAME
```

---

### 3. Database Independent

Your code doesn't change if you switch databases.

```
MySQL
↓

PostgreSQL
↓

Oracle
```

Only the JDBC driver and dialect change.

---

### 4. Automatic CRUD

Spring Data JPA provides

```
save()

findById()

findAll()

delete()

count()

existsById()
```

without writing any implementation.

---

### 5. JPQL

Write queries using Java entities instead of table names.

Instead of

```
SELECT * FROM employee
```

write

```
SELECT e FROM Employee e
```

---

### 6. Automatic Dirty Checking

```
Employee emp = repo.findById(1L).get();

emp.setSalary(50000);
```

No need to call

```
repo.update(emp);
```

When the transaction commits, JPA detects the change and executes the appropriate `UPDATE`.

---

### 7. Relationship Mapping

Easy mapping of

```
OneToOne

OneToMany

ManyToOne

ManyToMany
```

using annotations like

```
@OneToMany
@ManyToOne
```

---

### 8. Caching

JPA supports

- First-level cache (Persistence Context, enabled by default)
- Second-level cache (Hibernate feature, optional)

This reduces database hits.

---

### 9. Pagination & Sorting

```
Page<Employee> page =
    repo.findAll(PageRequest.of(0,10));
```

No manual `LIMIT`/`OFFSET` required.

---

### 10. Transaction Management

Works seamlessly with

```
@Transactional
```
