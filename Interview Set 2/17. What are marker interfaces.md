A marker interface is an empty interface that contains no methods or fields. Its purpose is to mark or tag a class so that the JVM or a framework can provide special behavior. 
For example, `Serializable` marks a class as eligible for serialization, and `Cloneable` indicates that an object supports cloning. Internally, Java checks whether an object implements these interfaces using `instanceof` before performing the operation. Although marker interfaces are still used in core Java, modern frameworks often prefer marker annotations because they are more flexible and can carry additional metadata.

# How does Java use Marker Interfaces?

Internally Java checks:

```
if(obj instanceof Serializable)
```

or

```
if(obj instanceof Cloneable)
```

and changes its behavior accordingly.

# Marker Interface vs Annotation



## Marker Interface

```
public class Employee implements Serializable {}
```

Checked using:

```
instanceof Serializable
```

Provides:

- Type information
- Compile-time type checking

---

## Marker Annotation

```
@Entity
```

or

```
@Component
```

Checked using:

Reflection.

Example:

```
clazz.isAnnotationPresent(Entity.class);
```

| Marker Interface           | Marker Annotation                |
| -------------------------- | -------------------------------- |
| No methods                 | No methods                       |
| Uses interface inheritance | Uses annotations                 |
| Checked using `instanceof` | Checked using reflection         |
| Provides type information  | Metadata only                    |
| Example: `Serializable`    | Example: `@Entity`, `@Component` |
