## Interview Answer
> ORM (Object Relational Mapping) is a technique for mapping Java objects to relational database tables. JPA (Java Persistence API) is a Java specification that defines a standard API and annotations for ORM, such as `EntityManager` and `@Entity`. Hibernate is the most widely used implementation of JPA. In a Spring Boot application, we typically program against JPA APIs, while Hibernate executes the actual SQL statements and manages entity persistence behind the scenes.

| Relationship  | Meaning                                           | Example                |
| ------------- | ------------------------------------------------- | ---------------------- |
| `@OneToOne`   | One entity is related to exactly one other entity | Person ↔ Passport      |
| `@OneToMany`  | One parent has many children                      | Department → Employees |
| `@ManyToOne`  | Many children belong to one parent                | Employees → Department |
| `@ManyToMany` | Many entities relate to many others               | Students ↔ Courses     |
`mappedBy` and `@JoinColumn` are never on the same side.
Exactly **one side** should own the relationship.

`mappedBy` is only needed when you want a **bidirectional relationship** (both entities reference each other) so Hibernate knows they represent the **same relationship** and doesn't create duplicate mappings.

| Annotation    | Default Fetch |
| ------------- | ------------- |
| `@OneToOne`   | EAGER         |
| `@ManyToOne`  | EAGER         |
| `@OneToMany`  | LAZY          |
| `@ManyToMany` | LAZY          |
>**Why does Lazy Loading improve performance?**

> Because the parent table already contains the foreign key. Hibernate initially loads only the parent entity and the foreign key value, creating a proxy for the associated entity. It avoids an additional query to fetch the complete associated object unless the application actually accesses it. This reduces unnecessary database queries and memory usage.

`@DynamicUpdate` is a Hibernate-specific annotation that tells Hibernate to generate dynamic SQL for updates. Instead of updating all columns of an entity, Hibernate generates an UPDATE statement containing only the columns whose values have changed. This can reduce unnecessary database updates, especially for entities with many columns.

`@DynamicUpdate` can have a performance trade-off: Hibernate has to generate SQL dynamically rather than reusing a fixed SQL statement, which can reduce SQL statement reuse/caching. So it isn't something you'd automatically put on every entity.

@DynamicUpdate → generates `UPDATE` SQL containing changed columns.

@DynamicInsert → generates `INSERT` SQL containing only non-null columns.
