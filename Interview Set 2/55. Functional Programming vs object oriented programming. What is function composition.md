

Interviewers ask this to test if you understand software design trade-offs, state management, and modern coding paradigms. Since Java blends OOP with FP features (Streams, Lambdas) and React relies heavily on functional principles (immutability, pure components), they want to see if you know _why_ and _when_ to apply each style rather than just reciting textbook definitions.
  

**FP vs. OOP Comparison**

|**Aspect**|**Object-Oriented Programming (OOP)**|**Functional Programming (FP)**|
|---|---|---|
|**Core Concept**|Models real-world entities using objects containing state and behavior.|Treats computation as the evaluation of mathematical functions without mutable state.|
|**State Management**|**Mutable state** encapsulated within objects.|**Immutable data**; transformations create new data instead of modifying existing data.|
|**Primary Unit**|Classes and Objects.|Pure Functions and First-Class Functions.|
|**Concurrency**|Requires explicit synchronization due to shared mutable state.|Inherently thread-safe because data is immutable (no race conditions).|
|**Reusability**|Achieved through Inheritance, Interfaces, and Polymorphism.|Achieved through High-Order Functions and Function Composition.|

**What is Function Composition?**

Function composition is the process of combining two or more simple functions to produce a new, more complex function. The output of one function becomes the direct input of the next:

  

$$\text{Result} = (f \circ g)(x) = f(g(x))$$

- **Java Example:** Chaining functions using `Function.andThen()` or `Function.compose()` (e.g., `Function<String, String> formatAndTrim = trim.andThen(toLowerCase);`).
    
      
    
- **React / JS Example:** Passing raw data through a pipeline of utility functions, or composing Higher-Order Components (HOCs).
    
      
    

**Your Interview Answer (Script)**

  

> "At a high level, **OOP** structures code around objects that encapsulate both state and behavior. It relies on mutable state and polymorphism, making it great for domain modeling where entities have distinct lifecycles.
> 
>   
> 
> **FP**, on the other hand, treats code as a series of pure, side-effect-free data transformations. It enforces immutability, which makes functions predictable, easy to test, and naturally thread-safe—something extremely valuable in concurrent systems like Spring microservices or modern React UI pipelines.
> 
>   
> 
> **Function composition** is a core pattern in FP where you combine small, single-purpose functions to build complex pipelines. Instead of writing one monolithic method, you pass the output of `Function A` into `Function B`. In Java, we do this using `Function.andThen()` or Streams, and in React, we see it when chaining array operations or composing custom hooks. It keeps the codebase modular and readable."
