[[15. Describe features of java 8]]

## What is Optional?

`Optional<T>` is a container object introduced in Java 8 that may or may not contain a value.

It is used to avoid `NullPointerException` by making the absence of a value explicit.

---

# Why was Optional introduced?

Before Java 8:

```
Employee emp = repository.findById(id);
System.out.println(emp.getName());
```

If `emp` is `null`, a `NullPointerException` occurs.

With Optional:

```
Optional<Employee> emp = repository.findById(id);
```

The caller is forced to handle the case where the value may be absent.

---

# Creating Optional

## of()

```
Optional<String> op = Optional.of("Vinay");
```

Use only when the value is guaranteed to be non-null. Passing `null` throws `NullPointerException`.

## ofNullable()

```
Optional<String> op = Optional.ofNullable(name);
```

Accepts both null and non-null values. If `name` is null, it returns `Optional.empty()`.

## empty()

```
Optional<String> op = Optional.empty();
```

Creates an empty Optional.

---

# Reading Values

## isPresent()

```
if (op.isPresent()) {
    System.out.println(op.get());
}
```

## isEmpty() (Java 11)

```
if (op.isEmpty()) {
    // no value
}
```

---

# Retrieving Values

## get()

Throws `NoSuchElementException` if the Optional is empty.

## orElse()

```
String value = op.orElse("Default");
```

Always evaluates the default value.

## orElseGet()

```
String value = op.orElseGet(() -> getDefaultValue());
```

Evaluates the supplier only if the Optional is empty.

## orElseThrow()

```
Employee emp = repository.findById(id)
        .orElseThrow(() -> new RuntimeException("Employee not found"));
```

Very common in Spring Boot.

---

# Transforming Optional

## map()

```
Optional<String> name = employee.map(Employee::getName);
```

## filter()

```
Optional<Employee> emp = employee.filter(e -> e.getSalary() > 50000);
```

## ifPresent()

```
employee.ifPresent(System.out::println);
```

## ifPresentOrElse() (Java 9+)

```
employee.ifPresentOrElse(
    System.out::println,
    () -> System.out.println("Not Found")
);
```

---

# Optional in Spring Boot

Repository:

```
Optional<Employee> findById(Long id);
```

Service:

```
Employee employee = repository.findById(id)
    .orElseThrow(() -> new EmployeeNotFoundException());
```

---

# orElse() vs orElseGet()

## orElse()

```
Optional.of("Java")
        .orElse(expensiveMethod());
```

`expensiveMethod()` is executed even if the Optional already contains a value.

## orElseGet()

```
Optional.of("Java")
        .orElseGet(this::expensiveMethod);
```

`expensiveMethod()` executes only if the Optional is empty.

# Common Interview Questions

- Why use Optional instead of null?

    - It forces callers to explicitly handle missing values and reduces `NullPointerException`.

- Can Optional contain null?

    - No. It either contains a value or is empty.

- Why avoid `get()`?

    - It throws `NoSuchElementException` if empty.

- Should Optional be used as a field?

    - No. Prefer using it as a return type.

- Should Optional be used as a method parameter?
    - No. Accept the object directly instead.

# Interview Answer

`Optional` is a container object introduced in Java 8 to represent the presence or absence of a value. It helps avoid `NullPointerException` by requiring callers to explicitly handle missing values. It is commonly used as a return type, especially in Spring Data JPA repositories. Common methods include `of()`, `ofNullable()`, `empty()`, `orElse()`, `orElseGet()`, `orElseThrow()`, `map()`, `filter()`, and `ifPresent()`. It should generally be used as a return type rather than as a field or method parameter.
