Cascade defines whether an operation performed on a **parent entity** should automatically be applied to its **associated child entities**.

Without cascade, Hibernate performs the operation only on the parent.

With cascade, Hibernate propagates the operation to the child entities as well.

## Interview Answer

Cascade Types define whether operations performed on a parent entity should automatically propagate to its associated child entities. For example, with `CascadeType.PERSIST`, saving a parent also saves its children. Other cascade types include `MERGE`, `REMOVE`, `REFRESH`, and `DETACH`, while `CascadeType.ALL` includes all of them. Cascading is configured on entity relationships such as `@OneToMany` and `@OneToOne` and is useful when the parent owns the complete lifecycle of the child. It is generally avoided on `@ManyToOne` because multiple child entities may share the same parent.

# orphanRemoval in Hibernate

`orphanRemoval = true` tells Hibernate to automatically delete a child entity when it is **removed from its parent's relationship**, even if the parent itself is not deleted.

The word **orphan** means:

> A child entity that no longer has a parent.

---

## Why Do We Need orphanRemoval?

Suppose we have:

```
@Entity
class Department {

    @OneToMany(
        mappedBy = "department",
        cascade = CascadeType.ALL,
        orphanRemoval = true
    )
    private List<Employee> employees;
}
```

```
@Entity
class Employee {

    @ManyToOne
    @JoinColumn(name = "department_id")
    private Department department;
}
```

Database:

```
Department
----------
1 IT
```

```
Employee
------------------------
101 Vinay   department=1
102 Rahul   department=1
```

---

## Without orphanRemoval

Suppose:

```
department.getEmployees().remove(employee);
```

The collection becomes:

```
Department
----------
Employees

Rahul
```

But the database still contains:

```
Employee

Vinay
Rahul
```

Hibernate simply removes the object from the Java collection.

It does **not** delete the row.

The child becomes an "orphan."

---

## With orphanRemoval = true

Same code:

```
department.getEmployees().remove(employee);
```

Hibernate detects:

```
Employee no longer belongs
to Department
```

During flush:

```
DELETE FROM employee
WHERE id = 101;
```

The row is automatically deleted.

## Why Do We Need Cascade?

Suppose we have:

```java
@Entity
class Department {

    @Id
    private Long id;

    @OneToMany(mappedBy = "department",
               cascade = CascadeType.PERSIST)
    private List<Employee> employees;
}
```

```java
@Entity
class Employee {

    @ManyToOne
    @JoinColumn(name = "department_id")
    private Department department;
}
```

Create objects:

```java
Department dept = new Department();

Employee e1 = new Employee();
Employee e2 = new Employee();

dept.setEmployees(List.of(e1, e2));
```

Now:

```java
entityManager.persist(dept);
```

Without Cascade:

Hibernate inserts only:

```text
Department
```

Employees remain transient.

You will get an exception similar to:

```text
TransientObjectException
```

because Hibernate finds unsaved child entities.

---

With:

```java
cascade = CascadeType.PERSIST
```

Hibernate automatically performs:

```text
persist(department)

↓

persist(employee1)

↓

persist(employee2)
```

No extra code is required.

---

# Cascade Types

## 1. PERSIST

Parent:

```java
entityManager.persist(department);
```

Hibernate also executes:

```java
persist(employee1);

persist(employee2);
```

Use when:

Saving a new parent should automatically save its children.

---

## 2. MERGE

Suppose:

```java
entityManager.merge(department);
```

Hibernate also merges:

```text
Department

+

Employees
```

Useful when updating detached object graphs.

---

## 3. REMOVE

```java
entityManager.remove(department);
```

Hibernate automatically removes:

```text
Department

↓

Employee1

↓

Employee2
```

SQL:

```sql
DELETE FROM employee;

DELETE FROM department;
```

Without `REMOVE`, deleting the parent may fail because of foreign key constraints if child rows still exist.

---

## 4. REFRESH

Suppose:

Database:

```text
Salary = 60000
```

Memory:

```text
Salary = 80000
```

Calling:

```java
entityManager.refresh(employee);
```

Reloads the entity from the database.

With:

```java
CascadeType.REFRESH
```

Hibernate also refreshes all associated child entities.

---

## 5. DETACH

Suppose:

```java
entityManager.detach(department);
```

Department becomes Detached.

With:

```java
CascadeType.DETACH
```

All child entities also become Detached.

Hibernate stops tracking them.

---

## 6. ALL

```java
cascade = CascadeType.ALL
```

Equivalent to:

```java
cascade = {
    CascadeType.PERSIST,
    CascadeType.MERGE,
    CascadeType.REMOVE,
    CascadeType.REFRESH,
    CascadeType.DETACH
}
```

Every operation performed on the parent is propagated to its children.

---

## Cascade Types Summary

| Cascade Type | Parent Operation | Child Operation |
| ------------ | ---------------- | --------------- |
| PERSIST      | persist()        | persist()       |
| MERGE        | merge()          | merge()         |
| REMOVE       | remove()         | remove()        |
| REFRESH      | refresh()        | refresh()       |
| DETACH       | detach()         | detach()        |
| ALL          | All operations   | All operations  |

---

## Where Is Cascade Used?

Most commonly:

```java
@OneToMany(
    mappedBy = "department",
    cascade = CascadeType.ALL
)
private List<Employee> employees;
```

or

```java
@OneToOne(
    cascade = CascadeType.ALL
)
private Passport passport;
```

Usually **not** on:

```java
@ManyToOne
```

because many child entities can reference the same parent.

Example:

```text
Employee A
      \
       \
Employee B ---> Department
```

Deleting one employee should **not** delete the shared department.

---

## Common Interview Questions on Cascade Types

### Does Cascade create foreign keys?

No.

Cascade only propagates entity operations.

Relationships are still defined by `@JoinColumn` or `@JoinTable`.

---

### Does Cascade work at the database level?

No.

Cascade is implemented by Hibernate/JPA.

It is different from database-level `ON DELETE CASCADE`.

---

### Should we always use CascadeType.ALL?

No.

Only when the parent truly owns the lifecycle of the child.

Example:

```text
Order
   |
OrderItem
```

Good candidate.

Example:

```text
Employee
   |
Department
```

Usually not.

Many employees share the same department.

---

### Does Cascade.REMOVE delete child records?

Yes.

If configured, Hibernate automatically deletes child entities before deleting the parent.
