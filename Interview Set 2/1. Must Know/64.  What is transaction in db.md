A **transaction is a sequence of one or more database operations that are treated as one logical unit of work**.

Mainly to maintain **data consistency and correctness** when multiple operations belong together.
Transactions provide the **ACID properties**:

|Property|Meaning|Interview example|
|---|---|---|
|**Atomicity**|All operations succeed or all are rolled back|Debit + credit both happen or neither|
|**Consistency**|DB moves from one valid state to another valid state|Account balance rules remain valid|
|**Isolation**|Concurrent transactions don't improperly interfere with each other|Two transfers shouldn't corrupt the balance|
|**Durability**|Committed changes survive failures|After COMMIT, data shouldn't disappear after DB crash|
### What are the steps of a Transaction?

At a high level:
```
BEGIN TRANSACTION
       ↓
Execute SQL operations
       ↓
Everything successful?
     /       \
   YES        NO
    ↓          ↓
 COMMIT      ROLLBACK
    ↓          ↓
Changes     Changes
saved       undone
```
