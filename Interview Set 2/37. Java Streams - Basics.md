## What is a Stream?

A Stream is a sequence of elements that supports functional-style operations such as filtering, mapping, sorting, and reducing data.

Unlike a collection, a Stream **does not store data**. It simply processes data from a source such as a List, Set, Array, or File.

---

## Why Were Streams Introduced?

Before Java 8, processing collections required explicit loops.

Example:

```
List<String> names = List.of("Alice", "Bob", "Andrew");

List<String> result = new ArrayList<>();

for (String name : names) {
    if (name.startsWith("A")) {
        result.add(name);
    }
}
```

Java 8 Streams provide a more declarative way:

```
List<String> result = names.stream()
                           .filter(name -> name.startsWith("A"))
                           .toList();
```

Instead of describing **how** to iterate, we describe **what** we want.

---

## Collection vs Stream

|Collection|Stream|
|---|---|
|Stores data|Processes data|
|Can be traversed multiple times|Can be traversed only once|
|Supports add/remove operations|Cannot modify data|
|Data exists in memory|Data flows through operations|
|Eager|Lazy (until terminal operation)|

---

## Stream Characteristics

- Does not store elements.
    
- Processes data from a source.
    
- Supports functional programming.
    
- Uses lazy evaluation.
    
- Can be consumed only once.
    
- Does not modify the original collection.
    
- Supports parallel processing.
    

---

## Stream Pipeline

A Stream consists of three parts.

```text
Source
   ↓
Intermediate Operations
   ↓
Terminal Operation
```

Example:

```
List<String> result = names.stream()
                           .filter(name -> name.startsWith("A"))
                           .map(String::toUpperCase)
                           .toList();
```

Pipeline:

```text
List
  ↓
stream()
  ↓
filter()
  ↓
map()
  ↓
toList()
```

## Source

A Stream starts from a source.

Examples:

```
list.stream()

Arrays.stream(array)

Stream.of(...)

IntStream.range(...)
```

---

## Intermediate Operations

Intermediate operations transform the stream.

Examples:

- filter()
    
- map()
    
- sorted()
    
- distinct()
    
- limit()
    
- skip()
    
- peek()
    
- flatMap()
    

Important:

Intermediate operations are **lazy**.

They don't execute immediately.

---

## Terminal Operations

A terminal operation triggers the execution of the stream.

Examples:

- collect()
    
- toList()
    
- forEach()
    
- reduce()
    
- count()
    
- findFirst()
    
- anyMatch()
    
- max()
    

Without a terminal operation, nothing happens.

---

## Lazy Evaluation

Example:

```
List<String> names = List.of("Alice", "Bob", "Andrew");

names.stream()
     .filter(name -> {
         System.out.println(name);
         return name.startsWith("A");
     });
```

Output:

```text
No Output
```

Nothing executes because there is no terminal operation.

Now:

```
names.stream()
     .filter(name -> {
         System.out.println(name);
         return name.startsWith("A");
     })
     .toList();
```

Output:

```text
Alice
Bob
Andrew
```

The terminal operation starts the pipeline.

---

## Streams Are Consumed Once

```
Stream<String> stream = names.stream();

stream.forEach(System.out::println);

stream.forEach(System.out::println);
```

Output:

```text
java.lang.IllegalStateException:
stream has already been operated upon or closed
```

Once a terminal operation executes, the stream is closed.

Create a new stream if needed.

---

## Does Stream Modify Original Collection?

No.

```
List<Integer> list = List.of(5, 3, 1);

List<Integer> sorted = list.stream()
                           .sorted()
                           .toList();
```

Original:

```text
[5, 3, 1]
```

Sorted:

```text
[1, 3, 5]
```

The original list remains unchanged.

## Common Interview Questions

### Is Stream a data structure?

No.

It is a data processing pipeline.

---

### Does Stream store data?

No.

It processes data obtained from a source.

---

### Can Streams modify collections?

No.

They create new results.

---

### Why can Streams be used only once?

After a terminal operation completes, the stream is considered consumed and is automatically closed to prevent inconsistent or repeated processing.

---

### Why are Streams lazy?

Lazy evaluation avoids unnecessary work.

Operations execute only when a terminal operation requires the result.

## Interview Answer

Java Streams, introduced in Java 8, provide a functional approach to processing collections. A Stream is not a data structure and does not store data; instead, it processes elements from a source such as a Collection or Array through a pipeline of intermediate operations like `filter()` and `map()`, followed by a terminal operation like `collect()` or `count()`. Streams are lazily evaluated, cannot be reused after a terminal operation, do not modify the original collection, and support parallel processing.
