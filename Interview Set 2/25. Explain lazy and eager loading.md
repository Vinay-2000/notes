Lazy and Eager are fetch strategies that determine when related entities are loaded. With **Lazy Loading**, Hibernate initially loads only the parent entity and creates a proxy for the associated entity. The associated entity is fetched from the database only when it is first accessed. With **Eager Loading**, Hibernate loads both the parent and its related entities immediately. Lazy loading generally provides better performance because it avoids fetching unnecessary data, whereas eager loading can result in additional queries and higher memory usage. By default, `@ManyToOne` and `@OneToOne` are EAGER, while `@OneToMany` and `@ManyToMany` are LAZY.
#### Default Fetch Types
This is asked very frequently.

| Relationship  | Default Fetch Type |
| ------------- | ------------------ |
| `@ManyToOne`  | **EAGER**          |
| `@OneToOne`   | **EAGER**          |
| `@OneToMany`  | **LAZY**           |
| `@ManyToMany` | **LAZY**           |

|Lazy|Eager|
|---|---|
|Loads data when accessed|Loads data immediately|
|Better performance|Can load unnecessary data|
|Uses proxies|No proxies for the association|
|Can throw `LazyInitializationException`|Doesn't have that issue for the eagerly loaded association|
|Preferred in most applications|Use only when you always need the related entity|

# What is Fetching?

Suppose you have:

```
@Entityclass Employee {    @Id    private Long id;    private String name;    @ManyToOne    private Department department;}
```

When you fetch an Employee:

```
Employee emp = employeeRepository.findById(1L).get();
```

Should Hibernate also fetch the `Department`?

This is determined by the **fetch strategy**.

---

# Lazy Loading

Lazy means:

> **Load the related entity only when it is actually accessed.**

Example:

```
@ManyToOne(fetch = FetchType.LAZY)private Department department;
```

---

Suppose database has:

Employee

|id|name|dept_id|
|---|---|---|
|1|Vinay|10|

Department

|id|name|
|---|---|
|10|IT|

---

When executing:

```
Employee emp = repository.findById(1L).get();
```

Hibernate executes:

```
SELECT *FROM employeeWHERE id = 1;
```

Notice:

```
Department is NOT loaded.
```

Instead, Hibernate creates a **proxy object**.

Memory:

```
Employee ├── id = 1 ├── name = Vinay └── department = Proxy
```

---

Later:

```
emp.getDepartment().getName();
```

Hibernate realizes:

```
Department not loaded yet.
```

Now it executes:

```
SELECT *FROM departmentWHERE id = 10;
```

This is Lazy Loading.

---

# Eager Loading

Eager means:

> **Load related entities immediately along with the parent entity.**

```
@ManyToOne(fetch = FetchType.EAGER)private Department department;
```

Now:

```
Employee emp = repository.findById(1L).get();
```

Hibernate immediately loads:

```
SELECT *FROM employeeWHERE id = 1;
```

and

```
SELECT *FROM departmentWHERE id = 10;
```

(or sometimes a JOIN depending on the query).

So when you call:

```
emp.getDepartment().getName();
```

No additional SQL is executed.

---

# Visual Comparison

## Lazy


---

## Eager

```

```

# Why Lazy is Preferred

Suppose:

```
Employee
```

has:

- Department
- Manager
- Address
- Projects
- Company

With Eager loading:

```
Employee   │Loads everything
```

Even if you only need:

```
employee.getName();
```

This results in unnecessary database queries and memory usage.

Lazy loading fetches data only when needed.

# Default Fetch Types

This is asked very frequently.

|Relationship|Default Fetch Type|
|---|---|
|`@ManyToOne`|**EAGER**|
|`@OneToOne`|**EAGER**|
|`@OneToMany`|**LAZY**|
|`@ManyToMany`|**LAZY**|

Many developers override `@ManyToOne` to `LAZY` because eager loading can hurt performance.

---

# LazyInitializationException

Suppose:

```
Employee emp = repository.findById(1L).get();
```

Transaction ends.

Hibernate Session closes.

Later:

```
emp.getDepartment().getName();
```

Hibernate wants to execute:

```
SELECT * FROM department...
```

But:

```
Session Closed
```

So it throws:

```
LazyInitializationException
```

because it can no longer load the missing data.

---

# Lazy vs Eager

|Lazy|Eager|
|---|---|
|Loads data when accessed|Loads data immediately|
|Better performance|Can load unnecessary data|
|Uses proxies|No proxies for the association|
|Can throw `LazyInitializationException`|Doesn't have that issue for the eagerly loaded association|
|Preferred in most applications|Use only when you always need the related entity|

# Common Interview Questions

### Q: Which one is better?

Generally:

```
LAZY
```

because it avoids unnecessary database queries.

---

### Q: Why is EAGER dangerous?

It can:

- Load unnecessary data
- Increase memory usage
- Generate extra SQL
- Lead to performance problems

---

### Q: Does LAZY mean "never load"?

No.

It means:

```
Load only when first accessed.
```

---

### Q: How is Lazy implemented?

Hibernate creates a **proxy object** instead of loading the actual entity immediately. When you first access the association, the proxy triggers a SQL query to fetch the real entity.
