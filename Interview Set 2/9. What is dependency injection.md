
Dependency Injection is a design pattern where a class receives its dependencies from an external source instead of creating them itself.
In Spring, the IoC container creates and manages beans and injects required dependencies into other beans. This reduces tight coupling, improves testability, and makes applications easier to maintain.
Spring supports constructor, setter, and field injection, with constructor injection being the recommended approach because it promotes immutability and makes dependencies explicit. Internally, Spring scans for beans, creates them in the ApplicationContext, resolves dependencies, and injects them during bean creation.

IoC is the broader concept where object creation and lifecycle management are delegated to the Spring container. Dependency Injection is the mechanism Spring uses to achieve IoC by injecting required dependencies into beans rather than allowing classes to create them directly.

### Types of Dependency Injection

## 1. Constructor Injection (Recommended)

```
@Service
public class UserService {

    private final EmailService emailService;

    public UserService(
            EmailService emailService) {

        this.emailService = emailService;
    }
}
```

Spring:

```
new UserService(emailServiceBean)
```

### Why preferred?
- Immutable dependencies
- Easier testing
- Detects missing dependencies at startup
- Works well with final fields

Most important answer for interviews.

---

## 2. Setter Injection

```
@Service
public class UserService {

    private EmailService emailService;

    @Autowired
    public void setEmailService(
            EmailService emailService) {

        this.emailService = emailService;
    }
}
```

Useful for optional dependencies.

---

## 3. Field Injection

```
@Autowired
private EmailService emailService;
```

Easy to write.

Not recommended.

---
### Why interviewers dislike field injection?
Harder to:
- Unit test
- Make immutable
- See required dependencies

## Q: How does Spring know what to inject?

By:
1. Type
2. Qualifier
3. Bean name
in that order.

During bean initialization. Spring first creates the bean instance using the no-arg constructor (or default constructor), then resolves dependencies and invokes the setter methods annotated with `@Autowired` before the bean is placed into the ApplicationContext for use.
