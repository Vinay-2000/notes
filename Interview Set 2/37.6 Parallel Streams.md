[[37. Java Streams - Basics]]
A Parallel Stream divides the stream into multiple parts and processes them concurrently using multiple threads.

Instead of using a single thread like a normal stream, it utilizes the **ForkJoinPool**.

---

# Why Parallel Streams?

Suppose you have:

```java
List<Integer> list = ... // 10 million elements
```

Sequential Stream:

```java
list.stream()
    .map(...)
    .filter(...)
    .toList();
```

Processing happens on one thread.

```
Thread-1

1 → 2 → 3 → 4 → 5
```

---

Parallel Stream:

```java
list.parallelStream()
    .map(...)
    .filter(...)
    .toList();
```

Processing happens on multiple threads.

```
Thread-1 → 1 2

Thread-2 → 3 4

Thread-3 → 5 6

↓

Merged Result
```

---

# How to Create

Method 1

```java
list.parallelStream()
```

Method 2

```java
list.stream()
    .parallel()
```

Both produce a parallel stream.

---

# Internal Working

Parallel Streams use Java's **ForkJoinPool.commonPool()**.

Execution flow:

```
Collection

↓

Spliterator

↓

Split Data

↓

ForkJoinPool

↓

Multiple Threads

↓

Merge Results
```

---

# Example

```java
List.of(1,2,3,4,5,6,7,8)
    .parallelStream()
    .forEach(System.out::println);
```

Possible Output:

```
5
2
8
1
7
3
4
6
```

Notice:

The order is **not guaranteed**.

---

# Maintaining Order

If order matters:

```java
list.parallelStream()
    .forEachOrdered(System.out::println);
```

Output:

```
1
2
3
4
5
6
7
8
```

# Stream vs Parallel Stream

| Stream                    | Parallel Stream                         |
| ------------------------- | --------------------------------------- |
| Single thread             | Multiple threads                        |
| Ordered                   | Order may change                        |
| Less overhead             | Thread management overhead              |
| Better for small datasets | Better for large CPU-intensive datasets |

---

# When Should We Use Parallel Streams?

Good candidates:

- Large datasets
- CPU-intensive computations
- Independent operations
- No shared mutable state

Example:

```java
numbers.parallelStream()
       .map(this::complexCalculation)
       .toList();
```

---

# When Should We NOT Use Parallel Streams?

Avoid when:

- Small collections
- Database calls
- REST API calls
- File I/O
- Shared mutable variables
- Order is important

---

Bad Example

```java
List<Integer> result = new ArrayList<>();

list.parallelStream()
    .forEach(result::add);
```

Multiple threads modify the same list.

Result:

- Race conditions
- Incorrect output
- Possible exceptions

---

# Thread Safety

Prefer immutable operations.

Good:

```java
List<Integer> result =
list.parallelStream()
    .map(n -> n * 2)
    .toList();
```

Bad:

```java
List<Integer> result = new ArrayList<>();

list.parallelStream()
    .forEach(result::add);
```

# Common Interview Questions

### Which thread pool is used?

```
ForkJoinPool.commonPool()
```

---

### Does parallelStream() always improve performance?

No.

Thread creation, splitting, and merging introduce overhead.

For small datasets, a sequential stream is often faster.

---

### Is order guaranteed?

No.

Use:

```java
forEachOrdered()
```

if order must be preserved.

---

### Can we use parallel streams for database calls?

No.

Database operations are I/O-bound, not CPU-bound. Parallel streams are intended for CPU-intensive tasks.

---

### Can parallel streams modify shared variables?

Avoid doing so.

Use immutable transformations or thread-safe data structures if necessary.

# Interview Answer

A Parallel Stream is a Stream that processes elements concurrently using multiple threads from the `ForkJoinPool.commonPool()`. It is useful for large CPU-intensive workloads where operations are independent. While it can improve performance by utilizing multiple cores, it also introduces thread management overhead and does not guarantee encounter order unless `forEachOrdered()` is used. Parallel Streams should generally be avoided for I/O-bound tasks such as database or network calls.
