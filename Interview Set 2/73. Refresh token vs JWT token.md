### JWT + Refresh Token Flow

After the user's initial authentication, the server issues **two tokens**:

1. **Access JWT** – short-lived token used to access protected APIs.
2. **Refresh Token** – long-lived token used to obtain a new access JWT.

React uses the access JWT for API requests. When the JWT is about to expire, React sends the refresh token to the authentication server.
**React shouldn't necessarily wait until the JWT is already expired.** It can refresh shortly before expiry, or retry after receiving a 401.

The authentication server validates the refresh token, typically by checking it against the database (e.g., whether it exists, is valid, not expired, and not revoked). If valid, it issues a **new access JWT**.

```
Login
  ↓
Authentication Server
  ↓
Access JWT + Refresh Token
  ↓
React
  ↓
JWT expires/approaches expiry
  ↓
Refresh Token → Auth Server → Validate against DB
                              ↓
                         New Access JWT
```
