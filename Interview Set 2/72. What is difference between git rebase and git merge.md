 **`merge` combines histories. `rebase` rewrites history to make it look linear.**
 
Suppose:

```
A---B---C        main
     \
      D---E      feature
```

## `git merge`

If you run:

```
git checkout feature
git merge main
```

Git creates a **merge commit**:

```
A---B---C---------M    feature
     \             /
      D-----------E
```

The original commits `D` and `E` remain unchanged.

### Advantages

- Doesn't rewrite existing history
- Safe for branches that are already shared
- Preserves the actual branching/merge history

---

## `git rebase`

If you run:

```
git checkout feature
git rebase main
```

Git takes your feature commits and **replays them on top of the latest main**:

```
A---B---C---D'---E'    feature
```

Notice:

```
D → D'
E → E'
```

They are technically **new commits** because their parent commit changed.

### Advantages

- Produces a cleaner, linear history
- Avoids unnecessary merge commits
- Makes `git log` easier to follow
